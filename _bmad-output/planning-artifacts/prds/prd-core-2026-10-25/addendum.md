# Addendum: smeta1 — технические решения и обоснования

Дополнение к PRD. Контракт — PRD; здесь фиксируются технические решения, которые не должны раздувать основной документ. Нормативные уточнения к PRD — §3, §4a, §4b и §5 (модель данных, API, миграция и доступ); остальное — обоснование. Актуальные инварианты — `docs/architecture-spine.md`.

## 1. Топология и границы

- Поли-репозиторная топология: `api-gateway`, `auth-users`, `company-org`, `estimate`, `pdf-extract`, `spec-service`, `llm-proxy`, `llm-gateway`, `rate-catalog`, `ui`, `deploy`.
- Наружу из бэкенда публикуется только `api-gateway`; UI — отдельный фронтенд-контейнер. Postgres и MinIO — только localhost.
- Один Postgres, отдельная база на сервис (AD-014); прямые чтения чужих БД запрещены.
- Очередь конвейера — таблица `spec_job` в Postgres (`FOR UPDATE SKIP LOCKED`), отдельный брокер не вводится.

## 2. LLM и приватность

- Локальная модель: `Llama-3.2-3B-Instruct-Q2_K.gguf`, CPU-only, `LLM_N_CTX=16384`, KV-cache `q4_0`.
- Рабочий облачный маршрут — `llm-proxy`: alias → локальный/облачный бэкенд, fallback, аудит.
- Каталог провайдеров/моделей — в `spec-service`; ключи не хранятся в БД, только `api_key_env`.
- Облако: `LLM_ALLOW_CLOUD`/`LLM_ALLOW_CLOUD_FALLBACK` + `X-Allow-Cloud`; payload без `structure_only` — осознанное исключение для chat-трафика.

## 3. Справочник и сопоставление

- Справочник глобальный/региональный, без `company_id`. Материал уникален по `(region_code, code)`.
- База 2022 — `material_base_price`; текущие цены — `material_price` по `(material_id, year, quarter, zone_code)`.
- Эмбеддинги — `intfloat/multilingual-e5-small` (384, CPU), HNSW cosine; импорт не считает векторы, их считает фоновый воркер или backfill.
- `POST /v1/rate-catalog/matches` — ближайшая цена за точный регион/год/квартал/зону; `confidence` — cosine, 4 знака; порог `needs_review` — 0.70.
- Текущий алгоритм возвращает top-1 без abstention; если кандидат неверен, пользователь помечает `reject` или исправляет ссылкой. Атрибуты/rerank/abstention — вне MVP (отложены).
- `estimate` сохраняет период в смете и обновляет его каждым успешным сопоставлением; правила повторного сопоставления — в FR-006/FR-007.
- Сопоставление по имени не гарантирует совпадение ЕИ; после привязки обязателен пересчёт количества в ЕИ справочника (раздел «Пересчёт ЕИ после привязки»).

## 4. Сметы и расчёт

- Версия сметы — полный снапшот позиций; ровно одна активная.
- Расчёт в `estimate`: Decimal, `ROUND_HALF_UP`, снапшоты `rate_snapshot_id`, `unit_snapshot`, `rate_amount_snapshot`, `qty_catalog_snapshot`, `conversion_factor_snapshot`; LLM не участвует.
- Стоимость: `cost = qty_catalog_snapshot × rate_amount_snapshot`; позиция без определённого пересчёта ЕИ в итог не входит (`conversion_required`).
- Рассчитанная версия заморожена; новые цены или правила пересчёта — только в новой версии.
- API diff сравнивает снапшоты без пересчёта, включая `qty_catalog`, `unit_catalog`, `conversion_factor`; UI diff — 1.1.

## 4a. Обратная связь и ручная привязка

- `estimate_item`: `reviewed_at`, `reviewed_by`, `status` (`proposed|confirmed|corrected|rejected|no_match`; ручное решение определяется `reviewed_at`), `correction_link`; `match_feedback` — append-only журнал решений `confirm`/`correct`/`reject`/`unmatch` со снимком запроса, предложенным/исправленным материалом, периодом и комментарием.
- Найденная при `match-rates` расценка сохраняется как `confirmed` с `reviewed_at=null`; повторное сопоставление обновляет такие позиции и пропускает ручные решения (`reviewed_at` заполнен).
- Review API принимает `rate_link` (URL из UI-маршрута `/prices`), `rate_code`, `material_id` или `unit_catalog`; цена материала проверяется за период/зону. `estimate_item.material_id` — ссылка на `material.id`, цена периода остаётся в `material_price`.
- `rate-catalog` отдаёт `GET /v1/rate-catalog/rates/lookup` по коду и периоду; UI-маршрут `/prices` использует `GET /v1/rate-catalog/prices?q=...` — поиск по коду ИЛИ наименованию.
- JSONL-экспорт: `python -m app.tools.export_match_feedback`; положительные/отрицательные пары, без автоматического обучения.
- UI: чекбокс «Верно» (`confirm`/`reject`), «Исправить» с модальным справочником за период сметы (пагинация по 50 строк), «Нет в справочнике» (`unmatch`), метка `исправлено: <логин>`, sticky-колонки; copy-link в `/prices` сохранён.
- `correct`/`unmatch` очищают `confidence`; `no_match` не показывает чекбокс.

## 4b. Пересчёт ЕИ после привязки

- **Владение.** `estimate` хранит словарь, правила и выполняет пересчёт; `rate-catalog` остаётся источником `material.unit` и цены; UI — редактор словаря и отображение. Прямых чтений чужих БД нет (AD-014).
- **Модель словаря.** Глобальная `unit_conversion_rule`: алиас/шаблон ЕИ, измерение (`length|area|volume|mass|count|package`), коэффициент к базовой единице, вид правила (`identity|dictionary|multiple|dimensions|package`), приоритет, признак включения, автор/время изменения. Изменения — append-only `unit_conversion_audit` (кто, когда, до/после, причина).
- **Поля позиции.** Исходные данные остаются в `qty` и `unit_orig`; добавляются `qty_catalog Numeric(18,4)`, `unit_catalog`, `conversion_factor Numeric(24,12)`, `conversion_source` (`identity|dictionary|dimensions|package|manual`), `conversion_reviewed_at/by`, `conversion_note`. При расчёте фиксируются `qty_catalog_snapshot`, `conversion_factor_snapshot`, `unit_snapshot`.
- **Правила и округление.** Приоритет, разбор размеров и упаковки, примеры и округление — в FR-018 (единственный источник поведения). Здесь фиксируются только хранение, владение и миграция; коэффициент — `Numeric(24,12)`, `qty_catalog` — 4 знака `ROUND_HALF_UP`, деньги — 2 знака.
- **Триггеры и поведение.** См. FR-018; в addendum не дублируются.
- **API/UI.** Поля `conversion_factor` и `unit_catalog` входят в `PATCH .../items/{item_id}`; отдельный маршрут пересчёта версии и CRUD словаря — через gateway. Детали поведения — FR-007/FR-018/FR-019; UI — проекция API.
- **Аудит.** Ручной коэффициент и ручная ЕИ пишутся в `match_feedback` (снимок, автор, причина); правки словаря — в `unit_conversion_audit`. Экспорт JSONL включает поля пересчёта.
- **Миграция.** Новые поля nullable; backfill рассчитанных версий не выполняется. Активные нерассчитанные версии пересчитываются по действию; позиции без правила получают `conversion_required`.
- **Влияние на архитектуру.** Затрагиваются AD-002 и модель данных; нужен AD о детерминированном пересчёте и глобальном редактируемом словаре. Состав эпиков и историй ведётся в эпик-артефактах.

## 5. Доступ и эксплуатация

- JWT HS256 (7 дней), проверка только на `api-gateway`; identity — заголовки `X-User-Id`, `X-Company-Id`, `X-Role`.
- Публичная регистрация — `estimator`; `admin` — bootstrap.
- Доступ к импорту, настройкам LLM и словарю — по §8 PRD (без серверной проверки `admin`).
- Браузерный e2e (Playwright) — блокирующий job; integration `pdf-extract` использует отдельную БД `pdf_extract_test`.

## 6. Рассмотренные альтернативы

- **Только облачная LLM** — отклонено: приватность и стоимость; локальный CPU-only остаётся основным.
- **LLM для сопоставления** — отклонено: дороже, нестабильнее и хуже объяснимо; выбраны эмбеддинги + cosine.
- **Отдельный брокер очереди** — отклонено для MVP: `spec_job` в Postgres достаточен.
- **Справочник на компанию и версии справочника** — отклонено: реальные данные региональные, а неизменность смет обеспечивают снапшоты.
- **Пересчёт цены вместо количества** — отклонено: цена справочника остаётся канонической; пересчёт количества прозрачнее и не искажает провенанс цены.
- **Статический словарь только в коде** — отклонено: упаковки, размеры и кратные единицы меняются без релиза; нужен UI и аудит.
- **LLM для размеров и коэффициентов** — отклонено: недетерминированно и необъяснимо; только грамматика, словарь и ручной коэффициент.
- **Атрибуты материала в справочнике** — отложено: текущий импорт не содержит структурированных веса/размеров; MVP парсит размеры из наименования, `unit_orig` использует как единицу количества, а при неудаче даёт ручной fallback.
- **Версионирование словаря ЕИ** — отложено до 1.1+; в MVP аудит и снапшоты рассчитанных смет.
- **UI diff в MVP** — отложен до 1.1; построчная валидация сопоставления реализована.
