# Epic 1 Context: Базовая инфраструктура и безопасность LLM

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Развернуть каркас микросервисной системы smeta1 и llm-gateway с жёсткой политикой обработки данных. Система должна подниматься локально одной командой (Docker Compose) и быть готовой к Kubernetes. Ключевая ценность эпика — заложить безопасные и воспроизводимые основы: локальный инференс LLM работает CPU-only на 8 ГБ ОЗУ без GPU, а облачный fallback по умолчанию запрещён и допустим только в режиме структурной редукции с аудитом. Этот эпик — фундамент, на который опираются все доменные сервисы.

## Stories

- Story 1.1: Каркас микросервисов и Docker Compose
- Story 1.2: Локальный CPU-only LLM-рантайм (q2–q3, 8 ГБ ОЗУ)
- Story 1.3: Политика облачного fallback и аудит

## Requirements & Constraints

- Система состоит из микросервисов: api-gateway, auth-users, company-org, estimate, pdf-extract, llm-gateway, mapping-service, rate-catalog, calc-service, ui. Внешняя инфраструктура: Postgres, MinIO (S3-совместимое хранилище). Каждый сервис имеет healthcheck.
- Локальный запуск — Docker Compose; целевой деплой — Kubernetes; конфигурация — через переменные окружения/env-файлы.
- Локальная LLM обязана работать CPU-only, без GPU, в пределах 8 ГБ ОЗУ (GGUF малых квантов q2–q3).
- Облачный fallback LLM: по умолчанию запрещён; при включении — только структурно-анонимизированные фрагменты (без наименований, количеств, ЕИ из смет); любое облачное использование фиксируется в журнале аудита (попытки, разрешения, отказы, объём структурных блоков).
- Целевые показатели производительности (для последующих эпиков, но влияют на инфраструктуру): обработка сметы 30–60 с при локальной CPU-only модели; PDF ≤ 5 МБ; 20–50 смет/мес; 100–500 позиций/смета.

## Technical Decisions

- **AD-003 (Гибрид LLM с редукцией):** `allow_cloud_fallback=false` по умолчанию; `redaction_mode=structure_only`; во внешнюю LLM только структурная схема без значений; аудит каждого облачного события.
- **AD-004 (CPU-only локальная LLM):** рантайм без GPU, лимит 8 ГБ ОЗУ, GGUF квантование q2–q3.
- **AD-009 (Поли-репо-топология):** каждый сервис — самодостаточный репозиторий в дереве `smeta/<service>/`; общий деплой — `smeta/deploy/` (docker-compose + k8s). Shared-lib на старте не вводится; общие контракты — только через API-схемы и сообщения.
- Стек сервисов: Python/FastAPI; ui — Vue; БД — Postgres; хранилище — MinIO. llm-gateway предоставляет единый интерфейс инференса независимо от рантайма (local/cloud).
- Оркестрация конвейера PDF→extract→spec→mapping→calc требует очереди сообщений, но конкретный брокер (RabbitMQ/Redis Streams/NATS/Kafka) — отложенное решение (Deferred), не фиксировать в этом эпике.

## Cross-Story Dependencies

- Story 1.2 и 1.3 зависят от Story 1.1 (каркас сервисов и llm-gateway должны существовать).
- Все доменные сервисы (Epic 2–7) опираются на инфраструктуру и llm-gateway из этого эпика.
- Epic 5 (извлечение спецификации, маппинг) напрямую зависит от политики LLM из Story 1.3 и локального рантайма из Story 1.2.
