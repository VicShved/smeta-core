# Epic 6 Context: Версионирование смет и детерминированный расчёт

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Дать сметчику сметы с несколькими версиями, из которых ровно одна активна, и детерминированный расчёт детальной и итоговой стоимости по сохранённым снапшотам. Эпик закрывает конец конвейера smeta1: проверенные сопоставления из Epic 5 превращаются в версионируемые позиции, а стоимость считается только по числовым снапшотам и фиксированным формулам — без участия LLM. Версии хранят полный снапшот позиций, поэтому изменение справочника не пересчитывает уже рассчитанные версии, а данные готовы к будущему diff (UI diff — 1.1).

## Stories

- Story 6.1: Создание сметы и версий (ровно одна активная)
- Story 6.2: Готовность к diff между версиями
- Story 6.3: Детерминированный расчёт стоимости

## Requirements & Constraints

- Смета привязана напрямую к существующему этапу договора (`estimate.stage_id`); уровень «подраздел этапа» упразднён.
- У сметы может быть несколько версий; ровно одна `is_active=true`. При активации новой версии предыдущая деактивируется атомарно.
- Каждая версия — полный снапшот позиций (не дельта); это даёт готовность к diff без отдельной инфраструктуры.
- Позиция (`estimate_item`) хранит: тип «материал/работа», наименование, исходную и нормализованную ЕИ, количество, раздел, ссылку на расценку, `confidence`, статус проверки и snapshot-поля.
- При расчёте версии сохраняются `rate_snapshot_id`, `unit_snapshot`, `rate_amount_snapshot`; `rate_catalog_id` — только провенанс и в расчёте не участвует. Изменение активной версии справочника не влияет на рассчитанные версии смет.
- Расчёт детальной и итоговой стоимости — только по числовым snapshot-полям и фиксированным формулам, 100% детерминирован; одинаковый вход даёт одинаковый выход. LLM не выполняет арифметику.
- API diff возвращает добавленные/удалённые/изменённые позиции (по количеству, ЕИ, расценке) на основе сохранённых снапшотов, без повторного расчёта. UI diff — 1.1.
- Объёмы MVP: 20–50 смет/мес, 100–500 позиций/смета.

## Technical Decisions

- `estimate` — отдельный FastAPI-сервис с собственной базой Postgres и миграциями Alembic; владеет сметами, версиями и позициями. `calc-service` — отдельный сервис детерминированного расчёта; прямые обращения к чужой БД запрещены, только API.
- `estimate_item` принадлежит версии и получает tenancy через `estimate.company_id`; все выборки фильтруются по `company_id` в репозитории. Доступ по id дополнительно проверяет компанию.
- Identity — только заголовки api-gateway (`X-User-Id`, `X-Company-Id`, `X-Role`); JWT внутренние сервисы не парсят. `company_id` обязателен; отсутствие identity — отказ. Наружу экспонируется только api-gateway.
- Слои внутри сервиса: domain → application → infrastructure → transport; domain/application не зависят от FastAPI/SQLAlchemy. Мутации — только через application use cases.
- Конвенции: UUID; время ISO-8601 UTC; ошибки RFC 7807 `application/problem+json`; списки `limit`/`offset`; версия API в пути (`/v1/...`); поля `snake_case`; денежные суммы — Decimal, не float.
- Целевой репозиторий — `smeta/estimate/`; деплой — общий `smeta/deploy/` (compose, отдельная база `estimate`).

## UX & Interaction Patterns

- Сметчик создаёт смету на этапе, получает первую активную версию и при необходимости создаёт/активирует новые версии.
- В простом UI отображаются детальная и итоговая стоимость; полноценный diff — 1.1.
- Ошибки понятны пользователю и не раскрывают внутренние детали сервисов.

## Cross-Story Dependencies

- 6.1 создаёт фундамент (смета, версии, позиции, снапшот-поля), на который опираются 6.2 и 6.3.
- 6.2 и 6.3 зависят от сохранённых позиций и снапшотов 6.1.
- Проверенные сопоставления и `confidence` приходят из Epic 5; Story 5.3 (API ручной проверки) отложена до появления фундамента 6.1.
- Snapshot расценок (Story 3.3) отложен до Epic 6: позиции принадлежат estimate, rate-catalog должен отдавать неизменяемые расценки версии по API.
- Простой UI Epic 7 показывает сметы, спецификацию, маппинг и стоимость.
