# Epic 3 Context: Справочник расценок

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Реализовать ведение справочника расценок: импорт только из Excel (.xlsx) через маппер колонок, версионирование импортов и snapshot-механизм, изолирующий уже рассчитанные версии смет от изменений справочника. Эпик создаёт источник расценок, на который опираются маппинг извлечённых позиций (Epic 5) и детерминированный расчёт стоимости (Epic 6): расчёт всегда воспроизводим, потому что опирается на зафиксированные на момент расчёта значения расценок и ЕИ.

Примечание: в каталоге planning-artifacts отсутствуют PRD, архитектура, UX-документы и файлы историй эпика — контекст составлен только по файлу эпиков.

## Stories

- Story 3.1: Импорт справочника из Excel с маппером колонок
- Story 3.2: Версионирование справочника
- Story 3.3: Snapshot расценок в позициях смет

## Requirements & Constraints

- Принимается только формат `.xlsx`; прочие форматы отклоняются с понятной ошибкой.
- Перед импортом пользователь сопоставляет колонки файла (наименование, ЕИ, цена/расценка и др.) через маппер.
- Импортируются только распознанные строки; некорректные строки помечаются с указанием причины и не попадают в справочник.
- Каждый успешный импорт создаёт новую версию справочника с полями: version, imported_at, source_file_hash, created_by.
- Справочник единый (не индивидуальный для пользователя), с полной историей версий; текущая активная версия определяется однозначно.
- Позиции рассчитанных версий смет хранят snapshot расценки/ЕИ: `rate_snapshot_id`, `unit_snapshot`, `rate_amount_snapshot`.
- Импорт новой версии справочника не изменяет активные версии смет и их итоговую стоимость.
- Повторный расчёт сметы на новых расценках возможен только при явном выборе другой версии справочника.
- Импорт и хранение версий — ответственность сервиса rate-catalog в микросервисной архитектуре.

## UX & Interaction Patterns

- Поток импорта: загрузка `.xlsx` → интерактивное сопоставление колонок → предпросмотр с пометкой некорректных строк и причин → завершение с созданием версии.
- Управление справочником (просмотр версий, выбор активной версии) в имеющихся планах описано на уровне API; отдельный UI для справочника в плане отсутствует.

## Cross-Story Dependencies

- Story 3.2 опирается на 3.1: версия справочника создаётся по итогам успешного импорта.
- Story 3.3 задаёт контракт с Epic 6: позиции версий смет (`estimate_item`) обязаны хранить снапшоты расценок/ЕИ, а расчёт стоимости — опираться только на снапшоты.
- Активная версия справочника читается сервисом маппинга (Epic 5) при сопоставлении извлечённых позиций со справочником.
