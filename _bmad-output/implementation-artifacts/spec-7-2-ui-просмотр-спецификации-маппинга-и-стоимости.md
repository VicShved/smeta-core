## Intent

**Problem:** Данные обработки сметы уже есть — позиции со стоимостью, сопоставлениями, `confidence` и итогом версии, — но интерфейс их не показывает: список смет даёт только название и номер версии. Сметчик не может ни увидеть спецификацию, ни понять, где требует проверки позиция, ни сверить итог.

**Approach:** Сделать экран сметы: таблица позиций активной версии (материал/работа, ЕИ, количество, раздел, сопоставление со справочником, `confidence`, стоимость позиции) и блок итогов. Позиции с `confidence < 0.70` выделяются; названия и коды расценок приходят из `estimate` вместе со снапшотами цены и ЕИ, по которым посчитана позиция.

## Boundaries & Constraints

**Always:** показывается активная версия сметы (активна ровно одна); UI — проекция: не пересчитывает стоимость, не округляет суммы, не применяет сопоставления; стоимость и итог отображаются как пришли от API; признак «требует проверки» берётся из ответа API (`needs_review`), порог не пересчитывается на клиенте; названия и коды расценок приходят обогащёнными от `estimate` (AD-014: справочник читается по API, не из чужой БД); снапшоты цены и ЕИ (`rate_snapshot_id`, `unit_snapshot`, `rate_amount_snapshot`) доступны в ответе позиции; ошибки — текстом без внутренних деталей; `401` — возврат к экрану входа; позиции читаются постранично, объём сметы — до 100–500 позиций.

**Never:** пересчёт стоимости, применение или исправление сопоставлений (валидация маппинга — 1.1); сравнение версий (UI diff — 1.1); выбор неактивной версии; обращения UI к `rate-catalog` напрямую; загрузка PDF и статусы обработки (7.1b); хранение бизнес-данных на клиенте, кроме access-токена; правка позиций, смет и справочника.

**Решения (2026-10-20):** названия и коды расценок обогащает `estimate` (UI не ходит в `rate-catalog`); в ответе позиции добавляются снапшоты цены и ЕИ; экран сметы показывает только активную версию; названия расценок `estimate` получает батчем — в `rate-catalog` появляется `GET /v1/rate-catalog/rates?ids=...` (любые версии справочника, скоуп компании), чтобы не было N+1 вызовов на страницу позиций.

## Implementation Notes

- **rate-catalog (патч-чтение)**: новый порт `RateCatalogRepository.list_rates_by_ids(rate_ids, company_id=...)` — выборка строк по списку id с тем же JOIN-скоупом, что и одиночное чтение: строки чужой компании неотличимы от неизвестных (AD-013). Use case `ListRatesByIds` (`app/application/list_rates_by_ids.py`) возвращает найденные строки; неразрешённые id просто не возвращаются.
- **rate-catalog (HTTP)**: `GET /v1/rate-catalog/rates?ids=<uuid,...>`; параметр принимает и список через запятую, и повторяющийся параметр (`?ids=a&ids=b`). Допустим только канонический вид UUID (`8-4-4-4-12`, hex в любом регистре) — `urn:uuid:…`, `{…}` и записи без дефисов дают `422`. Повторы одного id считаются один раз; предел — 500 **уникальных** id за запрос (`422`). Контракт строки тот же, что у одиночного чтения: `{id, code, name, unit, rate_amount}`. Порядок строк ответа — по `id` (порядок `ids` не сохраняется), поэтому ответ сопоставляется с запросом по `id`, а не по позиции.
- **rate-catalog (пустой результат)**: если не разрешился ни один id — пустой список `200 []` (как `GET /v1/rate-catalog/versions/current/rates`), а не `404`: `404` остаётся только за «сервис не знает такого маршрута» (старая сборка).
- **estimate (порт и клиент)**: `RateCatalogPort.find_rates(company_id, rate_ids) -> dict[UUID, RateRef]`; `HttpRateCatalogClient.find_rates` читает `GET /v1/rate-catalog/rates?ids=...`. Список id режется на чанки по 50 (`RATE_BATCH_CHUNK_SIZE`): страница позиций (до 500 id) не должна превращаться в запрос с ~18 КБ id — он не проходит по лимиту заголовков (16 КБ у uvicorn); предел провайдера (500 id) при этом не достигается. Ответы чанков объединяются. `200 []` — пустое обогащение (не ошибка); любой другой ответ, **включая `404`** (сервис не знает маршрута), — `RateCatalogUnavailable` (`502`): старая сборка rate-catalog больше не даёт молчаливого пустого обогащения. Строки вне запрошенных id игнорируются.
- **estimate (домен)**: `ItemView` (`app/domain/item.py`) — позиция плюс `rate_code`/`rate_name`; `ItemPage.items` теперь `tuple[ItemView, ...]`. Обогащение выполняется **только для позиций текущей страницы**: сначала срез, потом вызов справочника по уникальным `rate_catalog_id` (N+1 исключён). Позиции без `rate_catalog_id` справочник не спрашивают вовсе.
- **estimate (транспорт)**: `ItemResponse` дополнен `rate_code`, `rate_name` и снапшотами `rate_snapshot_id`, `unit_snapshot`, `rate_amount_snapshot` (AD-002). В ответах импорта позиций и ручной проверки `rate_code`/`rate_name` — `null`: обогащение есть только на пути просмотра. `cost` — как раньше, строкой с двумя знаками.
- **estimate (проверки)**: чужая/неизвестная смета или версия → `404`; недоступность rate-catalog → `502`; без identity → `401`.
- **ui (клиент)**: типы `EstimateItem`, `ItemsPage`, `EstimateDetail` (`src/api/client.ts`); `qty`, `cost`, `confidence` — строки, `needs_review` — признак из API, `material_work` — точный union `"material" | "work"`.
- **ui (экран)**: маршрут `/estimates/:estimate_id` (`src/router.ts`) → `src/views/EstimateView.ts`. Данные: `GET /v1/estimates/{id}` (смета и версии) и `GET /v1/estimates/{id}/versions/{vid}/items?limit=100&offset=N` (позиции страницами). Показывается **только активная версия**; версии без активной → сообщение, таблица не открывается.
- **ui (генерации запросов)**: счётчик поколения: поздний ответ по прошлой смете или по предыдущей странице позиций не переписывает текущий экран; при смене сметы данные прошлой сметы очищаются сразу (страницы разных смет не смешиваются в одной таблице).
- **ui (компоненты)**: `EstimateSummaryBar.vue` — номер версии, итог, время расчёта, число позиций и число требующих проверки (у нерассчитанной версии итог не показывается — «нет расчёта», и время расчёта без итога тоже не показывается; при ошибке загрузки позиций счётчики не выводятся); `EstimateTable.vue` — тип, наименование, исходная и нормализованная ЕИ, количество, раздел, сопоставление (код, название и снапшот: цена с двумя знаками и ЕИ, по которым посчитана позиция), уверенность, стоимость; `ConfidenceBadge.vue` — значение `confidence` и признак «требует проверки». Позиции с `needs_review` выделяются фоном строки.
- **ui (навигация)**: в списке смет этапа кнопка «Открыть» (`src/components/EstimateList.vue`, у кнопки `aria-label` с названием сметы) → `TreeNode.vue` → `HierarchyView.ts` → `router.push({name: "estimate"})`. Кнопка выбора сметы (панель стадий 7.1b) сохранена.
- **ui (пустые состояния и ошибки)**: нет активной версии / нет позиций / нерассчитанная версия / расценка не разрешилась — у каждого свой текст; ошибка загрузки позиций или сметы — текст без внутренних деталей и кнопка «Повторить»; `401` — возврат к экрану входа (обработчик клиента).
- **ui (пагинация)**: страница 100 позиций, подпись «показано N из M», кнопка «Показать ещё» (смещение = уже загруженное число позиций).

  - `ItemResponse` дополнен полями обогащения (`rate_code`, `rate_name`) и снапшотами (`rate_snapshot_id`, `unit_snapshot`, `rate_amount_snapshot`); в ответах импорта позиций и ручной проверки поля обогащения — `null`.
  - Обогащение выполняется только для позиций текущей страницы: справочник спрашивается один раз на страницу (чанками по 50 id).

## Design Notes

- Экран сметы: `GET /v1/estimates/{id}` (активная версия и её `total_cost`) + `GET /v1/estimates/{id}/versions/{vid}/items?limit=100&offset=...` (позиции страницами).
- Обогащение позиции: `rate_code` и `rate_name` приходят из `rate-catalog` по `rate_catalog_id`; при отсутствии строки поля остаются пустыми, позиция видна. Справочник читается батчем на страницу: `GET /v1/rate-catalog/rates?ids=...` (чанки по 50 id, ответы объединяются; порядок ответа — по `id`, сопоставление с запросом по `id`).
- Пустой результат батча — `200 []` (пустое обогащение); `404` — только «сервис не знает маршрута» → в estimate это `502`.
- Снапшоты в ответе позиции: `rate_snapshot_id`, `unit_snapshot`, `rate_amount_snapshot` — по ним видно, по какой цене и ЕИ посчитана позиция; в таблице показываются цена снапшота (с двумя знаками) и ЕИ снапшота; `cost` — из расчёта (6.3), пуст до расчёта.
- Денежные значения и `confidence` приходят строкой; UI не пересчитывает и не округляет (кроме показа цены снапшота с двумя знаками — округление по строке, без вещественных чисел).
- Подсветка: признак `needs_review` из ответа; порог `0.70` на клиенте не применяется.
- Пустые состояния: нет активной версии, нет позиций, нерассчитанная версия, расценка не разрешилась — у каждого свой текст.
- Постраничная подгрузка: `limit` 100, `offset` шагом 100, подпись «показано N из M» из `total`.
