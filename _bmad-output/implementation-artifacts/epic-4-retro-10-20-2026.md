## Findings

### Architecture delta

- **F4 — три независимых engine/sessionmaker на процесс.** `app/transport/routes.py:59,63` при `create_router()` вызывает `make_store_pdf`, `make_extract_text` и `make_get_text`; каждый создаёт свой `make_session_factory` (`app/wiring.py:21,60,92`, `app/infrastructure/db.py:11`). 4.2 добавила два пула к одному из 4.1. Это продолжает открытый action item Epic 2 и увеличивает число соединений/утечек при reload. Disposition: fix now.
- **F6 — валидация и извлечение используют разные парсеры.** 4.1 принимает файл по `PdfiumInspector` (`app/infrastructure/pdf.py:18`), 4.2 извлекает pdfplumber (`app/infrastructure/pdf.py:48`) и заново считает страницы; `file.meta.pages` и `file_text.page_count` не сверяются (`app/application/store_pdf.py:62`, `app/application/extract_text.py:52`). Документ, который pdfium разбирает, а pdfplumber нет, получает 201, затем 422. Disposition: fix now (контрактный тест/унификация), либо принять как явную границу.
- **F7 — ошибки storage расходятся между историями.** `put` не оборачивается (`app/infrastructure/storage.py:41`): сбой загрузки даёт 500 через общий handler; `get` оборачивает любые ошибки в `StorageUnavailable` (`app/infrastructure/storage.py:63`) и даёт 502. Один и тот же отказ MinIO выглядит по-разному. Disposition: fix now.

### Duplication and size

- **F8 — тестовая обвязка продублирована и уже разошлась.** `FakeStorage`, `_migrate`, `make_pdf`, `problem()`, `harness`, production-composition и reload `main` есть и в `tests/test_upload.py:33,49,491`, и в `tests/test_extract.py:36,66,447`; `make_pdf` имеет разные сигнатуры. `tests/conftest.py` нет. `tests/test_upload.py` — 507 строк, `tests/test_extract.py` — 471. Disposition: fix now (вынести в conftest).

### Pattern divergence

- **F9 — процессный разрыв review → done.** Build step-05 переводит story в `review`; walkthrough approval не меняет sprint-status; ретро пришлось вручную исправлять 4.1/4.2 на `done`. Evidence: `_bmad-output/implementation-artifacts/sprint-status.yaml:27-29`, шаг `_bmad/render/bmad-build/.../step-05-present.md`. Disposition: fix now (определить владельца перехода).

### Spec-to-implementation reconciliation

- **F2 — AC ≥95% не подтверждён на целевом корпусе.** `spec-4-2` прямо фиксирует отсутствие реальных ГРАНД/АВК PDF; `tests/test_extract.py:259` проверяет только сгенерированные reportlab-фикстуры, а coverage — отношение pdfplumber/pypdfium2, которое останется ~1.0 при согласованной деградации обоих парсеров. Disposition: fix now (корпус + эталон) или согласовать изменение AC.
- **F5 — целостность объекта между upload и extract не проверяется.** `ExtractText` читает объект без сверки с `file.size`/`meta.pages` (`app/application/extract_text.py:36`); тест `tests/test_extract.py:248-256` намеренно подменяет объект и ожидает извлечение новых байт. Артефакт может описывать не тот документ, что в строке `file`. Disposition: fix now (size/hash или явная модель tamper).
- **F10 — нет лимита страниц/символов.** В 5 МиБ можно упаковать PDF с большим числом страниц; E2E 0.8 МиБ / 500 страниц дал артефакт `content` 1.1 МБ. Ограничение страниц уже отложено из 4.1 (`deferred-work.md`). Disposition: fix now или подтвердить отсутствие лимита.
- **F11 — `%PDF-` ищется только в начале файла.** `app/application/store_pdf.py:51` использует `content.startswith(b"%PDF-")`; PDF-спецификация допускает заголовок в первых 1024 байтах, поэтому валидный файл с BOM/мусором перед заголовком получает 415. Disposition: fix now (искать в первых 1024 байтах, финальное решение — парсеру).
- **F13 — утечка нативной страницы при ошибке `get_textpage()`.** `app/infrastructure/pdf.py:38-44` закрывает `page` только в `finally` после успешного `get_textpage`; исключение до этого оставляет страницу открытой. Disposition: fix now (обернуть страницу целиком).
- **F12 — доверие identity-заголовкам.** pdf-extract принимает `X-Company-Id`/`X-User-Id` от любого сетевого пира; это соответствует AD-010/AD-013 (наружу только gateway, mTLS отложен). Disposition: accept as-is; зафиксировано, чтобы не переоткрывать.

### Verification-gap lens

- **F1 — gateway обрывает извлечение на 10 секундах.** `api-gateway/app/infrastructure/proxy.py:11` задаёт `DEFAULT_TIMEOUT_SECONDS = 10.0`; `extract` синхронный. E2E: PDF 0.8 МБ / 500 страниц → `POST /extract` вернул 502 на 10.002 с, при этом pdf-extract завершил работу и записал `file_text` (540 680 символов) позже; `GET /text` на 10-й секунде дал 404. Целевой объём 500 позиций / 20 страниц проходит за ~1.95 с. Disposition: fix now (per-route timeout ≥30 с или асинхронный 202).
- **F3 — нет интеграции с Postgres/MinIO в CI.** Все тесты — sqlite и fake/stub; `test_upgrade_head_uses_postgres_dsn_env_only` подставляет sqlite-URL. `.github/workflows/ci.yml` pdf-extract запускает только ruff/pytest; deploy CI — только `docker compose config -q`. Это открытый action item Epic 2. Disposition: fix now (CI services + compose smoke).

## Behavior verification

Проверено в живом compose (Postgres 18.6, MinIO, auth-users, api-gateway, pdf-extract):

- 5 страниц / 200 строк: upload 201, extract 200 за 0.21 с, `coverage=1.0`, `char_count=4604`; запись `file_text` и объект в `pdf-extract-files` присутствуют.
- 20 страниц / 500 позиций (целевой объём): extract 200 за 1.95 с, `coverage=1.0`, `char_count=11875`.
- 500 страниц / 0.8 МБ: gateway 502 на 10.002 с; артефакт всё равно закоммичен после таймаута (540 680 символов, 1.1 МБ контента), повторный вызов снова 502. Подтверждает F1 и F10.
- `pdf_extract` на существующем volume пришлось создать вручную (`CREATE DATABASE pdf_extract`) — известное ограничение initdb, зафиксировано в `deferred-work.md`.
