# Epic 7 Context: Простой UI

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Дать сметчику единое рабочее место: дерево «Компания → Договор → Этап → Сметы» с произвольной глубиной, загрузку цифровой PDF-сметы из интерфейса и просмотр результата конвейера — извлечённой спецификации, сопоставлений со справочником с уровнем уверенности, детальной и итоговой стоимости. UI показывает стадии обработки и запускает загрузку PDF и извлечение текста; маппинг и расчёт остаются доступны через API (без запуска из интерфейса). UI ничего не рассчитывает сам: это проекция того, что вернули API предыдущих эпиков. Полноценный UI валидации маппинга и UI diff между версиями сознательно отложены до 1.1.

## Stories

- Story 7.1a: UI — вход и дерево «Компания → Договор → Этап → Сметы»
- Story 7.1b: UI — загрузка PDF и статусы обработки
- Story 7.2: Просмотр спецификации, маппинга и стоимости

## Requirements & Constraints

- UI — read-only проекция домена: не пересчитывает стоимость, не применяет маппинг, не обращается к LLM, не меняет снапшоты расценок.
- Навигация: дерево «Компания → Договор → Этап → Сметы»; договоры хранятся как adjacency list с произвольной глубиной, поэтому дерево строится рекурсивно, без фиксированного числа уровней.
- Загрузка PDF из интерфейса: принимается только цифровой PDF (с текстовым слоем) размером ≤ 5 МБ; сканы и крупные файлы отклоняются понятным пользователю сообщением. Смета связывается с загруженным файлом.
- Отображаются статусы обработки: загрузка → извлечение → маппинг → расчёт.
- Экран сметы показывает таблицу позиций: материал/работа, исходная и нормализованная ЕИ, количество, раздел.
- Рядом с позицией видны сопоставление со справочником и `confidence`; позиции с `confidence < 0.70` выделены (та же граница, что в API: `needs_review`).
- Показываются детальная стоимость по позициям и итоговая стоимость активной версии сметы (активна ровно одна). Значения, включая цену снапшота `rate_amount_snapshot`, отображаются как пришли от API — клиент не пересчитывает и не округляет их (цена снапшота показывается без округления до 2 знаков).
- Подтверждение/исправление сопоставлений доступно через API; полноценный экран валидации маппинга и UI diff версий — 1.1.
- Одна роль и одна компания на пользователя: переключателя компаний и ролей в UI нет.
- Ответ 401 от API на любой запрос → возврат к экрану входа; ошибки показываются текстом для пользователя без внутренних деталей.
- Масштабы MVP: 20–50 смет/мес, 100–500 позиций/смета — таблица позиций должна оставаться пригодной для просмотра такого объёма.

## Technical Decisions

- `ui` — отдельный самодостаточный Vue 3.5 + Vite 5 SPA в `smeta/ui/`; общей библиотеки с бэкендом нет, связь только через версионируемые API-контракты.
- Единственная точка входа — `api-gateway` (JWT HS256, TTL 7 дней, refresh-токенов нет). UI хранит access-токен, сам JWT не разбирает и identity-заголовки не подставляет — это делает gateway.
- Контракты API: версия в пути (`/v1/...`), идентификаторы UUID, время ISO-8601 UTC, поля `snake_case`, списки с `limit`/`offset`, ошибки — RFC 7807 `application/problem+json`.
- Наружу экспонируется только api-gateway, внутренние сервисы доступны внутри сети; общий деплой — `smeta/deploy/`. Внутренние сервисы наружу не публикуются (`expose`, без `ports`); в compose наружу выходят api-gateway и сам UI.
- Конвейер обработки асинхронный, а выбор брокера очереди отложен: UI показывает статусы опросом API и не должен зависеть от конкретного транспорта конвейера.
- Соглашения проекта: Vue-компоненты — `PascalCase`, имена файлов и переменных — `snake_case`.
- Проблемные позиции определяются по `confidence`/`needs_review` из ответа API, а не повторным пересчётом порога на клиенте.

## UX & Interaction Patterns

- Сметчик открывает UI и видит экран входа (email/пароль) и отдельную форму регистрации; после входа — дерево с раскрываемыми узлами, переход к договору или этапу открывает список смет.
- Загрузка PDF — из контекста этапа/сметы; после загрузки UI показывает прогресс по стадиям обработки, а не пустой экран.
- Экран сметы: над таблицей — блок итогов активной версии (детальная и итоговая стоимость), в таблице — позиции с сопоставлением и `confidence`; низкоуверенные позиции подсвечены и заметны.
- Ошибки (невалидный PDF, превышение размера, 401/404) показываются текстом для пользователя без внутренних деталей сервисов; технические идентификаторы в интерфейс не выводятся.

## Cross-Story Dependencies

- Story 7.1a опирается на дерево договоров и этапов из Epic 2 (company-org) и на API смет из Epic 6 (estimate).
- Story 7.1b опирается на контекст этапа из Epic 2 (company-org) и на приём/валидацию файлов из Epic 4 (pdf-extract: только цифровой PDF ≤ 5 МБ).
- Story 7.2 опирается на результаты Epic 5 (спецификация, сопоставления, `confidence`, API ручной проверки 5.3) и Epic 6 (позиции со снапшотами, активная версия, детальная и итоговая стоимость, готовый API diff).
- Аутентификация и edge-контракт — Epic 2 (api-gateway): проверку токенов UI не реализует.
- Stories 5.3 и 6.3 должны быть готовы до 7.2, иначе показывать нечего.
- UI валидации маппинга и UI diff версий — 1.1, вне скоупа эпика.
