## Findings

### Verification gaps

- **F1 [high] — E2E сломан после Story 3.5: seed не передаёт обязательный `zone_code`.**
  `deploy/e2e/smeta_e2e/seed.py` отправлял `POST /v1/rate-catalog/imports` с периодом `region_code/year/quarter` без `zone_code`, а `rate-catalog` теперь требует `zone_code` (`rate-catalog/app/transport/routes.py:302`, схема `rate-catalog/app/transport/schemas.py:125`). Прогон `uv run pytest -q` в `deploy/e2e` 2026-10-25 дал 3 ошибки на фикстуре `seeded`: `422 ... query.zone_code Field required`.
  **Исправлено 2026-10-25:** в `fixtures.py` добавлен `RATE_ZONE_CODE = "3"`, seed передаёт его в период импорта/чтения и в ключ MinIO; заодно обновлено устаревшее ожидание заголовка `Обработка проекта`. Повторный прогон — **3 passed**.

- **F2 [high] — E2E-job в CI неблокирующий, поэтому регрессия F1 не гейтит поставку.**
  `deploy/.github/workflows/ci.yml:17-18`: `continue-on-error: true` с комментарием «стабильность набираем». Это объясняет, почему поломка seed после 3.5 осталась незамеченной. Наличие e2e есть, доказательства прохождения — нет.
  Disposition: **fix now** — e2e уже зелёный, но job всё ещё неблокирующий; убрать `continue-on-error` или сделать отдельный required job.

- **F3 [high] — Роль `admin` не проверяется на сервере.**
  UI объявляет `requires_admin` (`ui/src/router.ts:23`) и проверяет его в guard (`:69`), но ни один маршрут этот meta не выставляет: `/catalog` и `/settings/llm` защищены только `requires_auth` (`router.ts:43-59`). `rate-catalog` и `spec-service` не читают `X-Role` (grep по `app/transport` — пусто). Ссылки в шапке скрываются по роли (`ui/src/App.vue:61`), но прямой вызов API импорта справочника и настроек LLM доступен любому аутентифицированному.
  Disposition: **fix now** — серверная проверка роли для опасных операций либо явное решение «доступно всем», зафиксированное в AD-013/README.

- **F4 [medium] — E2E очистка ходит напрямую в шесть баз сервисов.**
  `deploy/e2e/smeta_e2e/cleanup.py:33-40,65-100` подключается по `SMETA_E2E_PG_DSN` к `estimate`, `company_org`, `auth_users`, `rate_catalog`, `pdf_extract`, `spec_service` и удаляет строки SQL-ом. Это тестовый harness, а не production-путь, но он обходит API и AD-014; при изменении схемы cleanup может молча перестать чистить.
  Disposition: **accept as test-only exception**; при следующем изменении схем — пересмотреть или перейти на API-очистку.

- **F5 [medium] — E2E не покрывает `match-rates` и ручную проверку/расчёт из UI.**
  `deploy/e2e/tests/test_key_path.py` проверяет вход, дерево, рассчитанную смету, загрузку и извлечение; маппинг и расчёт в seed идут через API (`seed.py:212`). Story 8.1 добавила в UI кнопку «Сопоставить со справочником», но e2e её не нажимает. Это уже не Epic 7, а следующий слой проверки.
  Disposition: **defer** — расширить e2e после исправления F1; владелец — Epic 8/следующая UI-история.

- **F6 [low] — Описание UI-пакета снова отстало от состава историй.**
  `ui/package.json:5` перечисляет только 7.1a/7.1b/7.2, хотя в UI уже 7.3–7.9, справочник цен, настройки LLM и `match-rates`.
  Disposition: **fix now** — обновить описание одной строкой.

- **F7 [process] — Story 7.9 смешана в одном коммите с 3.5 и 8.1.**
  `ui` `1626eca` — 18 файлов, +1 193/−133: email/роль в шапке, зоны справочника и статус эмбеддингов. Атрибуция истории по коммиту размыта, ревью и ретро вынуждены разбирать состав вручную.
  Disposition: **process lesson** — коммит на историю (или явно перечислять затронутые истории в теле).

- **F8 [medium] — Локальный прогон 7.7 использует живую БД `pdf_extract`.**
  `pdf-extract/tests/test_real_services.py:52` вызывает `migrate(os.environ["POSTGRES_DSN"])`; при команде из README это боевая dev-БД. Тест убирает строки, но не изолирует схему; CI использует отдельный service-контейнер. Для локального прогона нужна отдельная тестовая БД.
